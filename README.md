# 有序超市 · 社会实践的一天

五年级《顺序结构》课堂游戏。学生在前三站绘制流程图，最后一站拼接坐标积木，让人物逐步执行换柜、制作、养护和社区配送；教师统一开放操作、暂停和切章，并查看学生作品。

页面、像素场景、二维码和规则均由本项目提供，不需要外部素材或 CDN。支持在教师电脑本地运行，也可以部署到 VPS。

**VPS 部署：**见 [部署说明](DEPLOY.md)。GitHub Actions 按版本标签构建 GHCR 镜像，附带使用 `ghcr.milu.moe` 加速源、默认端口 `18790` 的 [Compose 配置](compose.yaml)。

## 启动

安装 **Node.js 24 或更新版本**，然后在本目录运行：

```sh
node --version
npm start
```

也可以直接执行 `node server.mjs`。项目没有第三方运行依赖，无需 `npm install`。服务使用 Node 内置 HTTP 和 SQLite；部分 Node 版本会打印 SQLite 实验性提示，不影响启动。

默认端口为 **8790**。启动终端会显示教师入口、本机检测到的学生局域网地址与后台密码来源，不打印密码：

- 教师电脑：`http://localhost:8790/teacher.html`
- 本机学生入口：`http://localhost:8790/`
- 学生平板：使用终端中的 `http://教师电脑局域网IP:8790/`。

端口占用时可以设置 `PORT`，例如 macOS / Linux 使用 `PORT=8791 npm start`。退出时在启动终端按 `Ctrl+C`。重启同一目录会继续使用原课堂数据。

## 课前连接平板

1. 教师电脑与学生平板连接同一个局域网；教师电脑在课堂期间保持开机、服务运行。
2. 在教师入口输入后台密码（未配置时读取本机 `data/teacher-key.txt` 中的原教师密钥），新建课堂。新课堂自动成为“当前接入课堂”，点击“邀请学生”。
3. 邀请框中选择学生可达的局域网地址，投屏二维码或学生链接。所有课堂共用同一个站点根地址。
4. 用一台平板打开地址或扫码，自动加入当前课堂并领取 A1、A2…学生编号，无需填写课堂码、组号或姓名。确认教师端出现该编号，并能显示“已进入当前章”。
5. 教师点击“开始操作”，在平板上添加一步并运行，确认地图与流程图同时显示。

平板不能使用 `localhost`，它代表平板自身。若连接失败，先检查地址、端口、同一网络、路由器的设备隔离，以及教师电脑防火墙是否允许 Node 的局域网访问。终端列出多个地址时，在邀请框选择实际使用的网卡地址。二维码完全在本地生成。

没有当前接入课堂时，学生入口等待教师开课，也可选择自由体验。自由体验通过 HTTP 页面打开，不要直接双击 `index.html`；记录只保存在当前浏览器，不会显示为已提交给教师。

## 学生怎样操作

横屏分为高度对齐的三列：左侧地图约33%，中间画布约46%，右侧工具约21%，画布最宽。竖屏时地图在上，画布与工具并排在下。点击地面探路，点击师傅交谈；电脑可用方向键或 WASD，输入文字时不会控制角色。

把右侧操作卡拖入中间画布添加步骤，点按操作卡只显示拖动提示。拖动画布中的卡片可调整顺序，拖回右侧工具区可以删除，误删可撤销恢复。接收和删除按卡片本身的面积判断：超过一半进入目标区域就生效，与鼠标或手指抓住哪里无关。修改输入后直接拖卡，也会先保存修改，再继续跟随指针。点选画布中的步骤可改名称和参数，也可用右侧按钮上移、下移或删除。步骤编辑区、添加操作和运行按钮都在右侧，给中间画布保留完整空间。顶栏和工具标题减少留白，运行、暂停、停止和提交按钮紧凑固定在右侧底部，选中步骤的文字与参数优先显示完整。所有流程图从上到下单列排列，连线和箭头标明执行顺序；常规任务使用紧凑尺寸，较长程序在画布内上下滚动，窗口变化时不折行。编辑完一步点“完成”，继续拖入。默认按排列连线；“手动连线”用于点选前后连接点，练习画出完整的顺序链。点击箭头可删除连线。左侧地图增加了纵向显示面积，地图画面随之放大。

点击“运行流程图”后，角色从本章初始状态开始，当前步骤与地图动作同步高亮。行走以5倍速播放，搬放和制作等动作以3倍速播放，任务计时仍按原规则计算。运行时地图探路不能改变任务路线；“暂停”保留进度，“停止”结束本轮并恢复初始现场。发生错误时修改标出的步骤，再运行。看师傅示范用于观察动作；自己的成绩来自自己的流程图。

| 章节 | 操作与目标 |
| --- | --- |
| 第一章：饮料换柜 | A 初始放橙汁、B 放牛奶、C 为空。一次搬一箱，目标必须为空。最后 A 放牛奶、B 放橙汁、C 为空；两种对称的三步方案都认可。 |
| 第二章：水果区鲜榨橙汁 | 清洗橙子→去皮切块→放入橙肉→启动机器榨汁→打包饮品。必须先放料再开机，空机启动会被阻止；每步都有材料变化。 |
| 第三章：实践岗位 | 课堂在人数最少的岗位中随机分配熟食、茶饮、植物或观赏鱼四个岗位，分配后固定保存。熟食制作海苔饭卷，依次铺海苔、铺米饭、放馅料、卷紧、切段装盒；茶饮遵守工序；植物填土后的浇水和标签可交换；鱼食领取与开盖、投喂后的合盖与记录允许合理换序。自由体验可自行切换岗位。 |
| 第四章：社区配送 | 六份订单已经取好，用“移动到（ , ）”积木沿多条道路送到 A–F。A、E含冷藏商品，关注时限；比较配送顺序、路线、总用时、成功单数和金币。 |

配送坐标按常见坐标系表示：向右，第一个数增大；向上，第二个数增大。例如 A（4,7）在 D（4,11）下方。路网上仅显示点位字母，坐标集中在地图左下、右下的清单中。A–F 是六个配送地址，A、E用蓝色雪花和呼吸圆环提醒优先配送。最下方道路从左到右为 G（4,3）、H（10,3）、I（16,3），右侧对应坐标卡可以直接拖入程序。点道路探路也可以查看该格坐标，内部的旧路口编号不在界面中显示。旧配送草稿会转换到新坐标，历史原始记录继续保留。

第四章使用蓝色拼接积木，始终按从上到下的单列顺序执行，较长程序可在画布内上下滚动。把右侧积木或坐标卡拖进画布；积木显示“移动到 E（10，11）”这样的地点与坐标，修改坐标后字母自动更新，未命名道路只显示坐标。括号中的两个数值可以直接修改，拖动积木可排序，拖回右侧可删除。整个画布和工具区都能接收拖放，积木超过一半进入目标区域即可放置或删除。拖动时积木略微缩小，以半透明浅灰色表示待放置状态；画布上的原积木会平滑挤开，轻微回弹后让出插入位置；换位置时连续移动，取消拖动后空位会收回。接缝处的蓝色微光表示前插，暖色微光表示后接；中线附近轻微移动不会反复切换。放置完成后积木恢复正常颜色与大小，块间保留小间隙。流程图卡片也使用同样的拖放方式。每块沿横向或纵向道路直走，转弯处再加一块；目标可以是道路上的整数坐标。途经地址就自动交付，无需再添加“送单”积木。走进建筑或用一块积木跨越拐弯，会指出需要修改的坐标。

走一格计1分钟，每单交付2分钟。思考、播放快慢、暂停和网络等待不计任务时间。按“到达地址”的时刻判断是否超时：冷藏 A、E 均须在26分钟内，D 是普通饼干订单，须在56分钟内；普通 B、C、F 分别须在50、66、62分钟内。冷藏单基础18金币、普通单基础12金币，每提前满4分钟加1金币；超时扣除该单基础金币；负数收益也会如实显示。六单全部处理后可以完成本轮，即使有失败单，也能保留记录并改进。

| 参考方案 | 行走 | 交付 | 总时间 | 结果 | 金币 |
| --- | ---: | ---: | ---: | --- | ---: |
| 基础示范，先到 A：W→H→G→A→D→E→B→C→F | 36分钟 | 12分钟 | 48分钟 | 六单成功 | 110 |
| 教师参考，折返兼顾：W→H→B→E→D→A→B→C→F | 36分钟 | 12分钟 | 48分钟 | 六单成功 | 117 |
| 先向右侧配送：W→H→B→E→F→C→B→A→D | 36分钟 | 12分钟 | 48分钟 | A 冷藏超时 | 84 |
| 较短的绕圈：W→H→B→A→D→E→F→C | 32分钟 | 12分钟 | 44分钟 | E 冷藏超时 | 83 |

相同路程也会因配送顺序得到不同收益；较短路线可能赶不上冷藏时限。穷举六单的720种首访顺序，可证明117金币是收益上界，折返方案能达到此值。游戏只展示110金币的基础示范，留给学生比较与改进。比较区按金币优先、用时次之选出同规则中最好的一轮。新配送草稿使用 split-cold-v2 规则；旧历史保留原订单、时限和收益，按当时规则回放，跨规则记录不混入最佳比较。恢复旧作品会生成当前规则的新草稿，不修改旧记录。
完成后点击“提交作品”，可写下安排的理由。“查看我的记录”（竖屏为“我的记录”）中查看自己的草稿、历史运行、提交与教师反馈，也可下载本机作品备份。自动保存与主动提交分开，修改后的新草稿不会改写旧运行，需再次提交。

## 教师怎样上课

课堂新建后自动成为当前接入课堂，学生打开站点即加入并自动编号。每章先讲解，再点击“开始操作”统一开放编辑与运行。

教师可在其他未结束课堂点击“设为当前接入课堂”；在该课堂开始操作、切章、下一章或恢复也会将其设为当前。结束或删除当前课堂会停止自动接入，不会自动回到旧课堂。已有学生刷新时保留同课原编号；当前课堂改变后进入新的当前课堂，旧课作品仍保留。

- “全班暂停”优先于学生本地继续；“恢复课堂”恢复暂停前状态。
- “下一章”保留当前作品，并将学生带到下一章讲解状态；再次点击“开始操作”才开放新章。
- 点击章节卡可回到指定章讲评或补做，原作品继续保留。
- “结束课堂”转为只读回顾，教师仍可查看与导出。
- 在线、已进入、完成和提交分别显示；查看作品可以读取尚未主动提交的同步草稿。
- 作品详情可选章节与历史运行，查看运行当时的流程图或配送积木、错误、逐步现场、配送逐单结果、用时和金币。选两位学生可并排讲评，第三章可按岗位筛选。
- 在作品详情发送文字反馈。换设备时，由教师在作品详情生成一次性恢复码，在新设备点右上角工牌，选择“换设备找回作品”并输入此码。正常加入与刷新无需输入恢复码。

切章时未跑完的尝试保留为中断记录，不能算成功完成。学生超前完成后留在本章等教师推进。第三章岗位跟随学生身份保存，刷新不会重新抽题。

## 保存、断线和身份

服务端默认保存在本目录的 `data/`：

| 文件 | 用途 |
| --- | --- |
| `supermarket.sqlite` | 课堂、学生、草稿版本、执行记录、提交、反馈和课堂指令。 |
| `supermarket.sqlite-wal` / `supermarket.sqlite-shm` | SQLite 运行时可能产生的辅助文件。 |
| `teacher-key.txt` | 未配置后台密码时使用的教师登录密钥；重启继续使用。 |

可用 `SUPERMARKET_TEACHER_PASSWORD` 设置自定义后台密码；Docker 可直接修改 Compose 对应值，或在 `.env` 中设置，详见 [部署说明](DEPLOY.md)。非空配置覆盖原教师密钥，已有数据卷也立即适用，无需删除课堂数据；留空继续使用原 `teacher-key.txt`。自定义密码不写入学生链接或页面，也不打印到日志。原教师密钥保存在本地数据文件；上述数据和密钥已通过 `.gitignore` 排除。可用 `SUPERMARKET_DATA_DIR` 环境变量选择另一个持久化数据目录。

学生浏览器另存本机草稿与待上传记录，并显示“保存在此设备”或同步状态。页面已经打开时，短暂断线可继续已开放章节；恢复连接后校准教师当前状态，再补传原章作品。

在 `localhost` 或 HTTPS 下，首次完整加载后会缓存学生应用，支持断线刷新。普通局域网 HTTP 受浏览器限制，不能安装离线应用缓存；此时断线期间请保留已打开的页面，刷新仍需能访问教师服务。教师页面与课堂数据不会写入离线应用缓存。

同一设备、同一浏览器、同一访问地址刷新时，自动恢复当前课堂原身份和 A1 等学生编号，不会重复领号。编号按课堂分别分配；清除站点数据或更换设备会成为新身份。不要在课中清除站点数据、切换浏览器或随意更换主机地址和端口；需要换设备时用教师恢复码。恢复码使用后旧设备失去课堂写入权限，旧设备尚未同步的内容仍可在“我的记录”中下载备份。服务端版本冲突会保留冲突稿，学生可以明确选择本机或课堂版本。

教师与学生身份可以在同一浏览器中分别使用。学生同时打开多个编辑标签时，后打开的页面转为只读，防止互相覆盖。

## 备份与恢复

课后先在教师端导出：

- “下载汇总”：CSV，适合查看各章完成和第四章首次、最新、最佳配送用时和金币。
- “作品备份”：JSON，包含流程图与积木程序版本、轨迹、提交与反馈。
- “打印作品”：可读作品页，可在浏览器打印或保存 PDF。

要完整恢复服务，先停止 Node 服务，再复制整个 `data/` 目录到备份位置；使用自定义数据目录时复制对应目录。恢复时保持服务停止，将备份数据目录放回原位置，然后启动服务。完整目录备份包含教师密钥，按课堂原始资料保管。

JSON 导出用于作品查阅、归档和后续处理，当前没有界面导入功能；恢复原课堂应使用数据目录备份。教师删除指定课堂会同时删除该课堂作品，删除前应先导出，其他课堂不受影响。

真实浏览器测试需另外提供 Playwright 和 Chrome / Chromium；它们只用于测试，不是游戏运行依赖。可用 `PLAYWRIGHT_MODULE` 指定 Playwright 模块，`CHROME_PATH` 指定浏览器路径：

浏览器测试使用独立临时服务与数据库，结束后清理；设置 `SUPERMARKET_TEST_OUTPUT` 可保留验收截图。课堂测试通过真实拖拽画出三步饮料换柜流程，并检查教师暂停、恢复、提交、回放、切章中断和岗位刷新。离线测试检查原章作品补传及教师反馈。配送测试通过真实鼠标及触摸拖入积木、拖回删除、撤销、修改坐标和运行，验证同为48分钟的117/84金币差别、旧规则历史隔离、暂停计时、果汁五步和实践区熟食岗位。拖放测试检查七项任务的标题、空白、过半面积判定、不同抓取位置、排序、删除与撤销，以及配送地点字母随坐标更新。吸附测试检查上下槽位、拖影对齐、中线稳定、松手顺序与取消清理。布局测试检查七项任务在多种窗口尺寸下的单列画布、三列对齐、中间列最宽、完整步骤编辑区、底部按钮、触摸拖动和连线。

已用 Chrome 验证四张地图、七项任务动画终态、暂停停止与地图 44×44 CSS 像素选点；已通过规则、接口和离线缓存测试。这不代替真实平板验收。

## 文件位置

- `public/`：学生端、教师端、本地二维码与 Canvas 像素地图。
